# Contributing Guide

## 브랜치 전략(GitHub Flow)
- main / feature/* 규칙
- 우리 팀이 GitHub Flow를 선택한 이유 (3줄 이내):

## 브랜치 네이밍 규칙
- 예: feature/<name>-<topic>

## 커밋 메시지 컨벤션
- 예: feat: ..., fix: ..., docs: ..., refactor: ...
- 금지 예: update, fix(대상 불명), wip, temp, final 등

## PR 작성 규칙
- 본문 필수 항목: 연결 이슈(Closes #번호), What, Why, How
- 병합 조건: 최소 1명 승인

## 코드 리뷰 규칙
- "LGTM"만 남기기 금지, 라인/파일 근거 코멘트 1개 이상
- 리뷰어-작성자 간 최소 1회 상호작용

## 충돌 대응 흐름
- 충돌 발생 → 팀 공유 → 해결 → docs/conflict-resolution.md에 기록
